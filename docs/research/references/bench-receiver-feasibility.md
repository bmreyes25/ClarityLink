# Independent receiver bench feasibility

At the pinned xcertplay revision, its README specifies Android 9/API 28 or newer, Android SDK Platform 37, USB Host/OTG hardware, and a legitimate supported MFi authentication method. The project uses a Java 25 Gradle toolchain for parts of its build. A Mac with Android tooling can support source study/build work, but a genuine receiver session requires compatible Android hardware and authorized authentication hardware/service. This campaign did not install or run xcertplay.

The source provides distinct main and cluster web outputs, stream diagnostics through its components, and offline/unit-testable negotiation and lifecycle paths. Its README reports device testing; this was not independently reproduced here. GPL-3.0 applies to the project.

Future genuine-session acceptance would require an authenticated iPhone connection; independently observed Type110 and Type111; separate configuration/frame delivery and verified stream identity; distinct display outputs; Type110 continuity; and correct teardown. It would not establish Honda compatibility. No iPhone, Honda authentication system, or vehicle was used. Before any bench experiment, identify the authorized MFi provider, supported hardware, USB topology, OS/build requirements, network isolation, and license implications.
