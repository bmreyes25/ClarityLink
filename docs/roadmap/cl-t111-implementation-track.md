# CL-T111 — firmware-specific native implementation track

- **Reconciled:** 2026-11-11
- **Parent plan:** [CL-MASTER-01](claritylink-master-plan.md)
- **Finish line:** [F1–F13 acceptance contract](finish-line-definition.md)
- **Goal:** genuine iPhone-origin Type111 navigation video on factory Display 1, simultaneous with normal factory Type110 on Display 0.
- **Safety state:** `safeForHonda() == false`. Vehicle deployment, Honda commands, live ADB/root, firmware changes, USB/iAP2 injection, credential extraction, authentication bypass, and live connected-iPhone testing remain prohibited.

This is an implementation program using bounded offline, firmware-specific work. It does not wait for Honda to add Type111 and does not presume an OEM extension API. An unsupported or unproven interface remains an engineering risk to resolve, not permission to fabricate a session or claim compatibility. Milestone completion requires the evidence listed below; a model result cannot promote a Honda or vehicle claim.

The stock invariants are factory authentication, Type110 audio/Siri/calls/controls, Garmin navigation, LaneWatch, backup camera, essential instruments and warnings, and reliable factory recovery. Every offline milestone must keep the Type110 owner and stream isolated; physical preservation of these functions remains unproven until a separately authorized target validation.

## Evidence corrections and unresolved interfaces

1. CL-61's initialized default Screen profile used a CFString UUID in genuine Honda CoreFoundation objects. This corrects older numeric assumptions for that tested profile only. UUID meaning, generation policy, and production-profile consistency remain unknown.
2. Keep the Honda descriptor geometry (960×540), Android Display 1 logical geometry (800×480), and physical Navigation aperture distinct. No transform or physical safe area follows from any one of these alone.
3. The recovered Honda `/info` builder describes one main display; inspected Type110 SETUP code has no Type111 handler. No UUID-to-streamConnectionID join was recovered.
4. CL-61 exercised genuine Honda constructor/helper functions and CoreFoundation objects through an offline harness. The helper entry was harness-owned. The actual displays callback requires a genuine Honda-created receiver session and Screen association; CL-62 did not have one. CL-65 also did not establish a session. No fabricated session, authentication state, callback, key, or port is accepted.
5. The exact unresolved native interfaces are: a real receiver-created session in the available offline runtime; callable stock entry/continuation with verified ABI; supported ownership/status behavior for an additive wrapper; receiver-owned authenticated Type111 security material and revocation; complete `/info` serialization; Type111 listener readiness and independent teardown; and the Display 1 admission, geometry, page, warning, and restoration contract.
