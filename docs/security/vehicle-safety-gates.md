This policy proposal itself performs no Honda ADB, vehicle connection, live iPhone session, authentication bypass, credential extraction, firmware modification, Honda APK installation, private Binder invocation/replay, Xposed modification, CAN transmission, warning override, or instrument-cluster takeover. C-P is a narrowly defined future exception only after the policy is effective and per-run gates pass.

## Future gate sequence

1. State one unanswered question and show why preserved offline evidence cannot answer it.
2. Define the minimum observation or intervention and its exact data/output boundary.
3. For C-P, obtain an independent technical review of the exact hash-pinned profile and command manifest, including command allowlist, head-unit resource impact, privacy, power state, connectivity, unexpected software behavior, and stop conditions. The reviewer must have relevant Android/ADB and automotive diagnostics competence; the approval artifact is a human attestation and this repository cannot authenticate identity or competence. For other live work, retain qualified independent vehicle-safety review.
4. Define parked conditions, responsible operator, stop conditions, rollback, and post-test factory checks.
5. After the C-P policy is effective and its review is approved, obtain separate informed owner approval for the exact run and serial. Other vehicle activities still require qualified independent safety review plus separate exact owner approval. This roadmap is not authorization.
6. Stop on any unexpected target, permission, output, warning, process, connectivity, or identity state. Do not broaden scope or retry outside approval.
7. Retain raw evidence privately and publish only a sanitized, source-pinned result.

For C-P only, the fixed PR #118 eight-phase profile is eligible for the independent technical review path; it is read-only host diagnostics around owner-guided ordinary CarPlay connect/disconnect and factory Navigation selection transitions. Its operations, exact serial requirement, per-command and aggregate time/output ceilings, owner-confirmed Park/parking-brake/power-state conditions, and private evidence boundary are immutable within this category. Stop without retry on unexpected behavior. The current fixed manifest permits 135 commands, with summed per-command ceilings of 2,425 seconds and 158,400,512 output bytes; these are worst-case bounds, not expected collection size or a safety finding. Diagnostic activity can consume head-unit resources, expose identifiers or personal data in raw output, perturb connectivity/timing, or trigger unforeseen target software behavior; factory UI transitions change active infotainment state temporarily; read-only ADB intent does not prove zero side effects. The independent reviewer must decide whether this aggregate workload and a specifically named electrical power state are acceptable for this vehicle. If power state, display behavior, target-side changes, or recovery are uncertain, use the existing qualified vehicle-safety review gate. CL-INT-01 cannot begin until receiver and display contracts, lab acceptance, and safety review pass. CL-VT-01 additionally needs a reversible procedure and separate exact test authorization. Never test while driving or deliberately generate unsafe vehicle warnings. If warning priority or restoration cannot be proved, record NO-GO.
