# Single-owner C-P multi-agent review policy

**Category:** `C-P-MA-OWNER-ASSUMED-RISK`
**Scope:** the exact eight-phase, 135-command PR #118 passive Honda observation profile only
**Status of this branch:** proposed; ineffective until adopted on protected `main`

## Decision model

This policy addresses a single-owner project in which the sole operator is also the person who accepts residual risk. It creates an explicit owner-assumed-risk path for a narrow, fixed passive diagnostic. It does not call an AI report an independent human review, a vehicle-safety certification, or proof that a procedure is safe.

Three records remain separate:

1. **Independent human safety review** is an assessment by a qualified external human. It remains a distinct review category for experiments and deployment outside this exception. This C-P owner-directed category does not require one.
2. **Multi-agent technical review** consists of separately produced Codex, Claude and ECC reports against the same exact reviewed commit, profile SHA-256, source SHA-256 map, command-manifest SHA-256 and eight phase IDs. Each report records tool/model version where available, findings with severity and `open`/`resolved` status, tests actually executed, unverified assumptions, proposed changes and `GO`, `CHANGES REQUIRED` or `NO-GO`. If no tests were run, assumptions not identified, or no changes proposed, state `not executed`, `none identified`, or `none` explicitly instead of omitting the record. The reports must be produced independently; a later reviewer must not rely on another agent’s conclusions. If any reviewer recommends changes/no-go or identifies unresolved high/critical findings, the procedure is not eligible until corrections receive fresh reviews.
3. **Owner risk acceptance** is Ben Reyes’s separate informed decision for one exact run, serial, electrical power state and reviewed source/profile hashes. The owner acknowledges the AI-review limitation and residual diagnostic risks. Owner acceptance is not a technical review and cannot waive the fixed safety boundaries.

The validator verifies record completeness, exact hashes, fixed review roles and recommendation fields, private artifact permissions and matching procedure scope. Required report fields must be nonblank. Tests actually run and unverified assumptions must each have an explicit entry; use `none` or `not executed` when appropriate rather than empty lists. It cannot authenticate that a report was produced by its claimed agent, establish reviewer independence or competence, or certify safety. Provenance therefore remains a transparent owner attestation and review artifact. Missing or unverifiable reports fail closed.

## Adoption and execution gates

This amendment is prospective. It becomes effective only after ordinary protected-branch review and adoption on `main`; this feature branch, its local tests, an owner statement, and an unmerged PR do not activate it. Before a live run, the controller refreshes `origin/main`, requires a clean checkout on `main` whose `HEAD` exactly equals current `origin/main`, and verifies the policy adoption commit is an ancestor of that remote `main`. The exact profile, source and manifest hashes are rechecked against the review records and the current checkout. After those checks, the controller displays the exact run scope and requests a fresh nonce challenge from the owner. A saved review/risk record contains no reusable `YES`; only an exact response to that invocation authorizes one run. The resulting decision, timestamp, nonce, serial, policy and content hashes are written to the private capture checkpoint before an ADB client is created. Decline or interruption requires a new owner confirmation for any later attempt.

The eligible profile is read-only unprivileged ADB. It contains eight phases and 135 fixed command entries; each command has a timeout no greater than 20 seconds and output limit no greater than 4 MiB. The current aggregate per-command ceilings are 2,425 seconds and 158,400,512 bytes. The controller also enforces a 3,600-second elapsed campaign deadline and a 300-second owner-prompt idle timeout. These are host-side software bounds, not measured resource use or proof of safe duration. `dumpsys` may consume head-unit resources; log output and diagnostic metadata may expose personal identifiers; normal CarPlay and factory Navigation transitions temporarily change infotainment state. Read-only intent does not guarantee zero side effects. The runner closes ADB stdin and handles command timeouts, output limits, and KeyboardInterrupt, but it cannot guarantee that a remote child exits when the host client closes, and SIGTERM/SIGHUP/SIGKILL do not all guarantee a failure card. Preserve incomplete private evidence and do not retry after interruption or transport loss.

The fixed power state is **ON mode, brake pedal not pressed, READY indicator absent**. The 2018 Honda Clarity PHEV owner's manual describes automatic engine start/stop during vehicle operation and defines READY as indicating the vehicle is ready to drive. Excluding READY is a conservative procedure choice; selecting EV operation does not prove that the engine cannot start. Head-unit and existing ADB availability in ON is unverified. A long ON-mode session may drain the 12 V battery; battery condition and ADB/head-unit tolerance have not been measured. A host-side 60-minute elapsed-session ceiling and five-minute owner-prompt idle timeout are software bounds, not evidence that a session of that duration is safe or that the battery will remain healthy. If the collector cannot proceed in ON, the required response is stop; READY, `adb root`, `su`, another privilege mechanism, or a configuration change is not a fallback. The owner controls all physical transitions. The session must be outdoors, stationary in Park, parking brake set, owner present, iPhone disconnected for baseline, and normal factory cluster/display/Navigation/audio confirmed. Before and after every collection phase, the live controller asks the owner to reconfirm Park, READY absent, no warning or abnormal cluster behavior, and normal visible display/cluster; baseline also asks that the parking brake is set and brake pedal is not pressed. If READY appears, the engine starts, any warning or abnormal behavior occurs, transport or process identity changes unexpectedly, or factory restoration is uncertain, stop and preserve evidence without retry. Loss of ADB between phases requires stop and ordinary-control restoration only; no retry or alternate transport. The campaign waits for each ADB client command to return before owner input; it does not stop or inspect a shared host ADB server, and cannot establish that server-side or remote child work has ceased.

The approved command manifest and source/profile pins may not be broadened by this policy. Exact serial, existing authorized ADB transport, unprivileged shell, private host-only raw evidence and existing stop/recovery rules remain mandatory. No capture runs while the owner performs a user-interface transition or waits for the next phase.

## Exclusions

This category does not authorize `adb root`, `su -c`, SuperSU execution, root reads, process attachment or instrumentation, Frida/ptrace, signals, memory writes, APK/helper installation, receiver changes, display control, HondaHack, firmware changes, CAN or other vehicle-control commands, warning interference, driving tests, deployment, or an automatic fallback. Privileged reads, HondaHack display observations, active Type111 instrumentation, receiver/display modification and deployment require separately scoped review and owner authorization under their own gates. `safeForHonda() == false` and `VEHICLE_DEPLOYMENT_NOT_AUTHORIZED` remain unchanged.

## Review record checklist

Each external review artifact stays outside public Git in owner-only private storage. The validator checks the report’s role label and SHA-256, reviewed commit, profile hash, source map, command-manifest digest, phase list, recommendation and required report fields. It cannot verify code-host identity or authenticity of an AI provider report. Review reports must cover:

- All command entries and legacy Android 4.2.2 ADB compatibility.
- Shell identity, process identity checks, command timeouts and output/resource ceilings, including the fact that legacy API-17 ADB exit codes do not reliably prove remote success.
- `dumpsys`, repeated diagnostics, logcat privacy and evidence handling.
- Process crash, ADB disconnection, stop/interruption behavior and restoration.
- Factory CarPlay and Navigation transitions, center display, cluster and warning behavior.
- PHEV electrical power state, ON/READY assumptions and unresolved head-unit stability risks.
- Tests actually run and assumptions that remain unverified.

No fabricated report, agent identity, tool version, finding disposition, human qualification or approval is accepted. The public status ledger records review availability and adoption state without publishing private reports or raw Honda evidence.
