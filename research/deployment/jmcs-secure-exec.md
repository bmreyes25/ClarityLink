# jmcs secure-execution evidence

Archived APP metadata identifies `/system/bin/jmcs` as mode 0755, owner 0/group 2000, with no setuid/setgid bits and no extended attributes observed. The init service executes it as root:root. On a conventional Linux exec with unchanged credentials and no file capabilities, `AT_SECURE` is not expected to be set by the ordinary credential transition.

That is an **inference**, not a Honda runtime fact: the active LSM/policy state, any security-domain transition, kernel secure-exec decision, and jmcs auxiliary vector were not recovered. Honda linker is hash-identified and includes UID/GID function names, but the secure-mode control flow is not traced. A bounded static scan did not find a direct call to the linker `getuid`/`geteuid`/`getgid`/`getegid` helper addresses, which does not exclude indirect calls or inline checks. Honda init has SELinux-related strings, while no named policy/context artifacts were found in inspected archives/filesystems. Do not state that SELinux is absent or that `AT_SECURE` is false. Current classification: expected `AT_SECURE=0` absent an LSM decision; actual value **UNKNOWN**. Honda linker's suppression behavior is also **UNKNOWN**.
