# Offline identification of the runtime `jmcs` port-5000 listeners

Date: 2026-09-29. Static review of the local symbolized `jmcs` ELF plus the Step 19 socket-inode correlation. No connection was made to port 5000.

## Finding

**PORT_5000_ROLE: UNKNOWN.** Runtime evidence establishes `jmcs`-owned IPv4 and IPv6 TCP listeners on port 5000 (FDs 17 and 18 at capture). Static analysis does not tie these exact sockets to a structured diagnostic/control protocol, or prove they are the ScreenSession endpoint.

`jmcs` has one identified listener helper, `ServerSocketOpen` (`0x2a0a34`), used by AirPlay receiver session setup. It creates TCP sockets, binds, listens, and can report the selected port via `getsockname`. The recovered ScreenSession setup path requests port `0`, stores the selected port, and places it into a property dictionary. That path therefore uses an ephemeral port, not a literal 5000. Static calls to the helper are in the AirPlay receiver setup family; the helper is not a generic debug command server. This does not explain the runtime port-5000 FDs, so attribution remains open.

| Field | Result |
|---|---|
| Function binding port 5000 | None identified in the static code reviewed. `ServerSocketOpen` binds its caller-supplied port; ScreenSession caller uses port 0. |
| Owner | Runtime socket inode correlation says `jmcs`; exact owning function unknown. |
| Purpose | Unknown. Not proven to be ScreenSession and not proven diagnostic/control. |
| Accept handler | No accept handler can be attributed to those specific FDs. `SocketAccept` (`0x2a0480`) belongs to the AirPlay ScreenSession helper path, but its endpoint is dynamically selected. |
| Protocol / parser | Unknown for port 5000. No static association between those runtime listeners and a parser/command table. |
| Read-only commands | Unknown; none should be assumed. |

Because static analysis does not prove that port 5000 accepts structured commands, command-table enumeration for that port is not applicable. `mc_server_init` does register a separate local `j_ipcs` service (`0x16`) with operation dispatch. It is not established as TCP port 5000 and no devmgr dump/list operation was found there.

Do not connect to port 5000 or treat it as a diagnostic endpoint. Existing listeners are only runtime inventory evidence, not an interface contract.
