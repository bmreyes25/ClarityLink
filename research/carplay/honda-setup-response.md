# Honda SETUP response and append boundary — Step 38

Setup creates an owned mutable response dictionary. `_AddResponseStream` (`0x284db8`) obtains the `streams` array or creates a `CFMutableArray`, appends an entry, and stores the array on the response dictionary. It releases its local array reference after `CFDictionarySetValue`; the dictionary retains the array. Type-110 entry construction sets `type=110` and dynamic `dataPort`, then appends it. Appending does not replace or reorder earlier entries.

On successful final status, Setup stores the response at the caller's output pointer (`0x286260`). `_connectionHandleMessage` receives the same object, sets surrounding request properties, and passes it to `_requestSendPlistResponse` (`0x289f60`), which serializes synchronously before returning. The caller then releases its owned response. Thus a post-Setup/pre-serialization append is structurally possible: copy or access the mutable dictionary/array, append an owned cloned entry, and preserve all stock entries. This is not live-hook safety proof.

CF ledger for a project-created response entry: create dictionary +1; set its fields (dictionary retains values); `CFArrayAppendValue` retains dictionary; replace/set response `streams` array (response retains); release local array and local entry references; leave the caller's response ownership untouched. On failure before ownership transfer, release temporaries and project resources. The serialized wire response still only has Honda Type-110 schema evidence. Type-111 field shape is MHI2 prior-art only: clone requested descriptor, set `dataPort` and `streamID=111`.
