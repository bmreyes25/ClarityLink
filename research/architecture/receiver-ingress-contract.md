It is not an API specification, proof that the API exists, a request to alter `jmcs`, or permission to contact the car. ## Acceptable external boundary

An interface must identify a **stock authenticated-session producer**, a documented/exported IPC or additive module entry, an admitted **separately running ClarityLink consumer**, and the exact lifecycle and security authority crossing that boundary. Source or binary evidence must show real producer and consumer callsites, not merely symbols or type names. A raw `AirPlayReceiverSessionRef`, mutable SETUP dictionary, generic TCP port, `devmgr_app_register`, singleton proxy callback, or navigation-status Binder is insufficient. The 2018 build has no proven candidate satisfying this contract.

| Requirement | Acceptance evidence required from a new OEM interface | Current missing edge |
|---|---|---|
| `/info` contribution | Version-matched producer/registration ABI for a secondary display descriptor, invocation timing, descriptor owner and correct stock response serialization. | Stock `ScreenCopyMain` yields only main display; no external contributor. |
| Type111 SETUP | Typed request delivery, endpoint negotiation, success/error response ownership, response serialization and rejection/rollback path; explicit additive behavior. | Reviewed `AirPlayReceiverSessionSetup` skips Type111. |
| Stream endpoint | Who creates/binds/listens/accepts or transfers an FD, endpoint/peer binding, port/FD lifetime and failure cleanup. | Stock Type110 listener is receiver-owned; no secondary handoff. |
| Session association | Opaque stable identity plus generation, stream ID binding, reconnect invalidation and stale-callback rejection; no raw cross-process pointer. | No external stock session key or generation. |
| Authentication/security | Honda remains factory authentication owner; contract grants only necessary authorized per-stream capability, with scope, revocation and protected handling; no key or credential extraction. | No Type111 security/delegation ABI or authorized ClarityLink context. |
| Caller admission | Exact UID/signature/permission and registration method on Android 4.2.2; evidence that a no-APK temporary native consumer is admitted if that remains a constraint. | Exported components and C symbols do not prove caller access. |
| Teardown | Stop, parent disconnect, error, unregister and process-death behavior; project resources close idempotently without touching Honda-owned resources. | Only internal Honda finalizers and project-owned models are known. |
| Type110/audio isolation | Secondary start/failure/stop cannot replace the stock screen callback, delegate, Type110 listener, audio, calls, Siri or controls. Demonstrate fan-out/additive semantics rather than registration priority displacement. | No observed non-displacing extension. |

**Acceptance sequence:** (1) verify provenance and exact build compatibility; (2) trace the entire producer → endpoint → admitted consumer path and call ABI; (3) independently review permissions, security and lifecycle; (4) add candidate-scoped positive proofs to the P1-C5 catalog and reclassify explicitly; (5) re-run all A–L gates and ownership tests; (6) only then draft a separately authorized, bounded validation plan. A statically credible interface may become **conditional and testable**; deployment additionally requires matching live Honda validation, safe Display 1 admission, source authenticity and no contradictions. The decision engine must never infer any of these from symbolic consistency alone.

## Related-image provenance and compatibility procedure

1. Record lawful source, acquisition time, model/year/trim/region and firmware/build identifiers; retain original bytes read-only, privately, outside Git. Record file size and SHA-256 for the image and each extracted `jmcs`, proxy and relevant module. Avoid distributing proprietary binaries or certificates.
2. Establish package and extraction chain: partition/file path, container format, extraction tool/version, parent image hash and mapping to extracted file hashes. Check ELF class, ARM ABI/endian, build ID if present, SONAME, `DT_NEEDED`, exports/imports, relocations and loader paths. A shared name or version string is not equivalence.
3. Compare the **exact** Honda Clarity hashes above with the candidate image. If different, keep addresses/callgraphs segregated. Build a symbol/callsite correspondence table with both hashes and version-specific addresses. Confirm whether the additional registration is actually reachable in that image and whether this Clarity build has a compatible entry/loader/IPC.
4. Reject cross-image portability claims absent a documented compatible ABI, dependency set, caller identity and stock-preserving lifecycle. A newer Honda/Acura Type111 decoder can show lineage or a design idea; it does not prove this receiver can load, authenticate or delegate to it. No binary transplant or credential use follows.

**Reopening evidence:** a compatible OEM extension contract meeting the table, or an independently reviewed revised integration boundary with the same security and Type110 protections. Route-guidance metadata requires its own authentic app-content producer and permissioned subscriber. An independent companion route must carry its own provenance label. Every future code/catalog update and live test needs separate review; this contract itself authorizes no Honda or iPhone action.
