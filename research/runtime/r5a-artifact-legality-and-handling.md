# R5A — artifact legality and handling

1. Use public or otherwise lawfully accessible research sources only. Record source URL/location, access date, stated license/terms, model/build/version, filename, and SHA-256 in local notes.
2. Do not commit proprietary Honda binaries, firmware/update payloads, Apple/MFi code, private captures, keys, identities, VINs, MAC addresses, endpoints, or raw proprietary dumps. Keep permitted artifacts local and ignored.
3. Commit only hashes, filenames, versions, source/licensing notes, and independently derived factual notes needed for reproducibility. A hash is not permission to redistribute the underlying file.
4. Do not bypass access controls, use leaked credentials, or redistribute restricted artifacts. Do not vendor third-party reverse-engineered proprietary code into ClarityLink.
5. Respect third-party licenses and attribution requirements. Keep clean-room notes: separate observation from inference, avoid copied implementation text/code, and cite permitted sources.
6. Before reviewing any newly acquired binary, establish lawful possession and analysis rights, provenance, exact version, and a local-only storage plan. If any is unclear, record `TYPE111_INSUFFICIENT_ARTIFACT` and stop that artifact review.

@ECC handling review checked scope against the milestone prohibition on proprietary binary commits and restricted Apple/MFi material. No new private/proprietary artifact was acquired for R5A.
