## API-version correction to R4A

The [R4A cluster note](43t1-r4a-cluster-rendering-architecture.md) asked whether Display 1 advertises `FLAG_PRESENTATION`. The current Android API reference dates `Display.FLAG_PRESENTATION` to **API 19**; [AOSP API-17 Display.java](https://android.googlesource.com/platform/frameworks/base/+/android-4.2.2_r1/core/java/android/view/Display.java) contains no such flag. In API 17 the relevant category uses the HDMI display **type**. This corrects the test question without rewriting the historical R4A note. Current documentation may describe a flag-based `Presentation.show()` rule for later Android versions; that rule must not be projected onto Honda's API-17 baseline.

**Static conclusion:** `Presentation` is the best public API-17 candidate for an independently owned app window. It remains `POSSIBLE_BUT_NEEDS_EVIDENCE` on Honda. App identity, display policy, z-order, physical crop, and lifecycle under Honda's service are unproven. A generic Android API does not authorize installation or on-car testing.
