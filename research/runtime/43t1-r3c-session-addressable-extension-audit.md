## Ownership and lifecycle conclusions

- Honda creates a 16-byte application context from `_AirPlayHandleSessionCreated`, installs its own 44-byte delegate and later passes that context to its own finalizer handler. This is occupied Honda state, not a free opaque slot.
- `AirPlayReceiverSessionSetDelegate` and `AirPlayReceiverServerSetDelegate` copy complete fixed-size records. Their behavior is replacement, not merge or append.
- Setup receives a session pointer and builds a mutable response graph. That proves Honda's internal context, not an external entry point. The response is released after synchronous serialization and cannot provide later cleanup ownership.
- The destroy event is global and lacks session identity. The connection-to-session close edge is conditional. The finalizer's session pointer does not establish stable generation identity or project callback access.
- `streamConnectionID` is used in Type110 setup, but no recovered mapping connects it to a session destroy event, project state, or Type111 teardown. Do not infer uniqueness, immutability, or reuse behavior.
- No candidate evidences create → Setup → same-identity cleanup through an additive route. Unknown fields remain `UNKNOWN`; they are not available sidecar slots.

**Conclusion:** no existing non-replacement, session-addressable extension/ownership path is statically usable. The strongest Honda paths are occupied callback records and internal transaction state. No project sidecar architecture is statically supported because Setup observation and cleanup subscription are both missing as additive, same-identity endpoints.
