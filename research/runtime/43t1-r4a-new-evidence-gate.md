# 43T1-R4A — new-evidence watchlist and authorization gate

**Default state: `NOT AUTHORIZED`** for runtime interposition, Type111 Honda negotiation, Honda RAM experiment review, and any live car experiment. This file is a watchlist, not an authorization. [R3C ADR](../adr/43t1-r3c-entry-and-ownership-architecture.md) remains controlling until new evidence is reviewed in a separately scoped milestone.

## Evidence that could reopen *research*

| Possible new item | What it must actually prove | Current status |
|---|---|---|
| Newly preserved Honda artifact or different library | Identity/hash/provenance; actual caller/import or additive pre-serializer Setup callback; mutable request/response; stock Type110 unchanged | `UNKNOWN`, absent in R3C set |
| Honda factory update with Type111 | Explicit Type111 parse/response, stream factory, start/control/teardown, session identity, ownership and security path | `UNKNOWN`; current parser skips 111 |
| Supported module-load mechanism | Existing nonpersistent, supported launch/registration path for exact `jmcs` build without init/binary change, callback replacement or runtime write | `UNKNOWN`; R3C found no such path |
| Service/Binder extension | Same native session/generation key, original Setup payload and mutable response before serialization, add/remove lifecycle and security boundaries | `UNKNOWN`; current app-service status APIs lack this |
| Honda-specific Type111 cleanup evidence | Type111 child enumeration/teardown or independently paired project-owned closure on every failure path | `UNKNOWN`; R3B found current cleanup insufficient |
| Public legacy-AES Type111 receiver implementation | Protocol/schema/security comparison only, with source/version and test provenance | `EXTERNAL_PRIOR_ART`; cannot alone reopen Honda integration |

**Do not reopen runtime interposition unless at least one listed evidence item is obtained and reviewed.** Even one positive item only reopens static study; an implementation proposal must then satisfy the *combined* R3C gate: additive entry, session identity, Setup request/response access, no inline patch or thread-stop assumption, no Honda runtime write to enter, independently bounded project cleanup, and Honda-only Type110 ownership. The current evidence does not satisfy it.

## Separate authorization boundaries

| Activity | Required future evidence/review | State after R4A |
|---|---|---|
| Runtime interposition | Above full static entry/ownership gate plus exact provenance and ECC safety review | **NOT AUTHORIZED** |
| Honda Type111 negotiation | Full entry/ownership gate **and** Honda-specific schema/security/media/lifecycle compatibility, failure rollback and a separately approved experiment | **NOT AUTHORIZED** |
| Honda RAM experiment review | A new, narrowly scoped user request, independently justified safety/restoration evidence and review; R4A gives no permission even to schedule one | **NOT AUTHORIZED** |
| Live car experiment of any kind | Separate explicit user authorization, exact read/write/target limits, physical safety and privacy review, no inference from this watchlist | **NOT AUTHORIZED** |

The independent cluster-renderer direction has a **different gate**: supported Display 1 access by a project-owned process, physical safe area and z-order behavior, stock warning visibility, Type110/audio coexistence, a lawful own navigation source, and privacy/expiry behavior. An offline turn-card model satisfies none of these Honda runtime gates by itself.
