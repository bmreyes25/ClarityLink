# R7E6 process containment proof

The diagnostic creates exactly one direct child for each allowed mode. The parent records the PID returned by `fork()`, arms its watchdog, polls/waits only for that PID, and on timeout sends `SIGKILL` to that exact child before waiting for the exact PID. The child arms its own alarm before entering the operation and exits with `_exit()` from its watchdog handler. The signal handler avoids allocation, I/O, locks, and cleanup frameworks. The parent restores default `SIGCHLD` disposition before forking so inherited ignore state cannot auto-reap the child.

The PID-reuse argument is scoped to this direct-child relationship: an exited child that has not been waited on remains a zombie and retains its PID until reaped. This does not generalize to PID values discovered through `ps`, unrelated processes, or external management.

Host tests pass (9 focused watchdog cases), including normal return, child busy-loop and sleep timeout, parent timeout, crash mapping, inherited ignored `SIGCHLD`, fork failure, waitpid error recovery, and repeated host lifecycles. The API17 x86 emulator runtime also passed these fault cases and 100 repeated version/self-test pairs. Exact parent/child PIDs were recorded directly from the supervisor and checked absent through their exact `/proc/<pid>` paths. Test-only fault modes are excluded from the ARM production binary.

The production parent/child internal bounds are 4/2 seconds. The Test A host command timeout is 12 seconds, strictly greater than the 4-second internal maximum. On any host timeout, the collector classifies a watchdog/transport anomaly, stops, preserves local evidence, and issues no more target command. It does not reintroduce external `ps`/`kill`. This evidence is host and API17 x86 proof; it does not prove Honda ARMv7 runtime semantics.
