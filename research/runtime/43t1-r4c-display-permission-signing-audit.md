# 43T1-R4C — display permission, manifest and signing audit

**Reviewed set:** preserved `AndroidManifest.xml` for `ExternalDisplayOutService`, `ExternalDisplayApService`, `Navigation`, `CarPlay`, and `CarPlayService`; their relevant decompiled Binder/service entrypoints; AOSP `android-4.2.2_r1` permission declarations and window policy. No package was installed and no package-manager state was queried.

| Surface | Manifest and code evidence | Ordinary-app implication |
|---|---|---|
| Honda externaldisplay render host | [Manifest](../../resources/ExternalDisplayOutService/AndroidManifest.xml) requests `SYSTEM_ALERT_WINDOW`, `INTERNAL_SYSTEM_WINDOW`, `VEHICLE_RW`; declares a persistent app, exported service and exported customization activities/boot receiver. The service's [`onBind()`](../../decompiled/ExternalDisplayOutService/sources/com/mitsubishielectric/ada/app/externaldisplay/ExternalDisplayOutService.java) returns null. No `sharedUserId` is declared in the decoded manifest. `HONDA_CONFIRMED` static. | Exported declaration supplies no Binder pixel endpoint; starting activities or service does not grant access to its private root. |
| ExternalDisplay AP service | [Manifest](../../resources/ExternalDisplayApService/AndroidManifest.xml) requests `VEHICLE_RW`, has an exported AP service with no component-level `android:permission`; [Binder](../../decompiled/ExternalDisplayLib/sources/com/mitsubishielectric/ada/appservice/externaldisplay/IExternalDisplayApService.java) is control/status/notification oriented. `HONDA_CONFIRMED` static. | No arbitrary content API. Absence of a manifest bind gate does not establish method-level permission success or safe use. |
| Navigation service | [Manifest](../../resources/Navigation/AndroidManifest.xml) requests `VEHICLE_RW`, `ACCESS_MAP`, location/storage and system-related permissions; [Navigation Binder](../../decompiled/NavigationLib/sources/com/mitsubishielectric/ada/appservice/navigation/INavigationApService.java) carries semantic route/guidance operations. `HONDA_CONFIRMED` static. | A semantic guidance call cannot be treated as a View/Surface/Bitmap sink. It could alter Honda Navigation behavior and is not a ClarityLink render path. |
| CarPlay app/service | [Manifests](../../resources/CarPlay/AndroidManifest.xml) and [service manifest](../../resources/CarPlayService/AndroidManifest.xml) request `VEHICLE_RW` and export selected app/service components. `HONDA_CONFIRMED` static. | No independent Display 1 content ownership is evidenced; receiver integration stays rejected by R3C. |
| API-17 `SYSTEM_ALERT_WINDOW` | [AOSP manifest](https://android.googlesource.com/platform/frameworks/base/+/android-4.2.2_r1/core/res/AndroidManifest.xml) classifies it `dangerous`; [AOSP PhoneWindowManager](https://android.googlesource.com/platform/frameworks/base/+/android-4.2.2_r1/policy/src/com/android/internal/policy/impl/PhoneWindowManager.java) checks it for type 2006 `TYPE_SYSTEM_OVERLAY`. `DOCUMENTED_ANDROID`. | Generic API-17 normal app could request it, subject to grant and Honda policy `UNKNOWN`. A full-screen overlay over factory content creates unresolved warning/z-order risk. |
| API-17 `INTERNAL_SYSTEM_WINDOW` | Same AOSP manifest declares it `signature`; policy uses it for other system window types. `DOCUMENTED_ANDROID`. | A normally signed app cannot rely on it. Whether Honda granted it to its package is not a ClarityLink entitlement. |
| `VEHICLE_RW` / `ACCESS_MAP` | Uses appear in the preserved package manifests; no defining `<permission>` with protection level was found in this reviewed manifest set. `UNKNOWN` definition/grant. | Do not claim a normal app can obtain these Honda permissions, or that either is needed for a public `Presentation`. |

**Signing conclusion:** the decoded reviewed manifests do not establish a shared UID or third-party signing route. `INTERNAL_SYSTEM_WINDOW` would require matching platform/signature authority under AOSP. A public API-17 `Presentation` does not inherently require Honda's service permissions in generic AOSP, but Honda Display 1 admission remains `UNKNOWN`. Installing as a system/privileged app, obtaining Honda signature, using Xposed, or replacing a service is outside R4C and not a justified substitute for a supported ordinary-app path.
