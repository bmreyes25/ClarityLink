## Canonical contract and ECC findings

The [43T0-C approved plan](43t0c-identity-gated-delta-ecc-review.md) is the specification. ECC evidence-first, security-review, and fail-fast error-handling guidance was applied to the [Mac-side collector](../tools/step43t0d0_collector.py), its sole process callsite, fixed allowlist, user input, output writes, bounds, state gates, and privacy. No independent external ECC reviewer capability was available; this is a documented ECC-method review.

The collector has an independently fixed target-command allowlist: seven identity suffixes—`shell id`, `shell cat /proc/version`, and five separate selected `shell getprop <key>` reads—plus five network suffixes: `shell cat /proc/net/dev`, `shell cat /proc/net/route`, `shell cat /proc/net/ipv6_route`, `shell cat /proc/net/if_inet6`, and exactly `shell ifconfig` with **zero arguments**. Host enumeration is only `adb devices`. No socket-table recapture, `/proc/<pid>`, binary pull, arbitrary path, fallback utility, or target write is reachable. The allowlist is independent of the approved plan; the collector **does not import** the dry-run module at runtime. It verifies the approved 43T0-C source SHA-256 before host enumeration and refuses any drift. Tests compare its entire emitted command sequence to the canonical dry-run plan, replacing only `<validated-current-target>` with the fake endpoint: **exact equivalence, 1 host enumeration + 7 identity reads + 15 network reads**.

Dry run is the CLI default. It prints the 43T0-C-equivalent plan and creates no output directory or process. A deliberate `--execute-approved-43t0-delta` flag plus an explicit ADB binary path and verified historical 40E manifest are required for future execution. That branch was not exercised here. The historical manifest is checksum-pinned and supplies a host-private endpoint used only as an additional equality check, never physical identity proof. A differing endpoint stops with `CURRENT_ENDPOINT_DIFFERS_FROM_40E`/`IDENTITY_MISMATCH`; there is no override.

## Process and command safety

There is one process-spawn callsite: `subprocess.Popen` inside a bounded runner, with `shell=False`, no stdin, and a tuple argv. It executes only the explicitly selected local ADB file; argv retains the canonical `adb` token. The CLI requires the exact historical `/opt/homebrew/bin/adb` path, executable file, and reviewed SHA-256. If Homebrew changes the binary, execution stops for offline re-review. No PATH search, arbitrary executable, host shell, `eval`, `exec`, target shell string, redirection, retry, root, service control, or network-repair path is present. The collector has no socket import and never probes a listener or port.

The runner reads stdout/stderr incrementally with a selector and a combined **64-KiB hard memory/capture limit**, checks a **5-second deadline**, kills the child on oversize or timeout, and never treats truncated output as success. Nonzero or uncertain shell/transport status stops. Tests exercise stdout-only and mixed-stream oversize, timeout, and a pinned executable path using local Python—not ADB. The source audit and allowlist tests reject `su`, `adb root`, `push/pull`, state-changing utilities, `ifconfig` arguments, `/proc/<pid>/mem`, shell metacharacters, and unapproved argv. The only filesystem mutation is Mac-side private capture/manifest creation.

## Identity and phase state machine

The future run enumerates once and accepts exactly one `device` target. It then requires the operator's explicit parked-Honda confirmation **before any target read**, compares the current endpoint to the checksum-verified historical endpoint, and performs the seven fixed reads in the approved order. Full normalized `id` and `/proc/version` hashes plus all five exact property values must match. The `id` prefix must prove UID/GID 2000; root or changed groups fail. The states are `IDENTITY_NOT_CHECKED`, `IDENTITY_INCOMPLETE`, `IDENTITY_MISMATCH`, and `IDENTITY_MATCH`; only `IDENTITY_MATCH` releases network reads. No best-effort or manual override exists.

Baseline additionally requires human confirmation that CarPlay is disconnected. Connected reads wait for the human to connect normal wired CarPlay and confirm center display, audio and stock cluster are normal. Post-disconnect reads wait for a normal disconnect and stock-state confirmation. Final stock sanity confirmation is required for `SUCCESS`. The five fixed reads occur once per phase, in exact order. A denied confirmation returns `USER_ABORT` or `STOCK_SANITY_FAILURE` and emits no later command.

Any **observable** ADB transport failure, disconnect, or reconnect stops the same run without retry or re-enumeration. Fake-runner tests inject transport failures after identity, baseline, and connected reads and confirm no later command. The fixed 43T0-C command contract provides no continuous transport monitor; a fully silent reconnect between successful ADB invocations cannot be proven absent. The collector does not claim otherwise. The current endpoint remains fixed with `-s`, and a new run requires full enumeration, human confirmation and identity checks. This residual does not justify adding an unreviewed host or target command to this observational delta.

## Host storage, formats, and failure behavior

Execution requires a **new** directory outside Git. It is created on the Mac with mode `0700`; raw files and `manifest.json` use `0600`. Existing paths and paths inside the repository are rejected. The approved `identity/`, `baseline/`, `connected/`, and `post-disconnect/` layout is followed; host enumeration is additionally saved under `preflight/devices.raw`. No Honda-side files exist. The private manifest records collector version, approved-plan commit, current project commit, collector source hash, UTC start/update/end, phase, command index, exact argv, redacted target reference, result class, return status, byte counts, and stdout/stderr SHA-256. Raw stderr is stored privately only when present. There is no upload, Git API call, or automatic commit.

Before advancing, `/proc/net/dev`, IPv4 route, IPv6 route, `if_inet6`, and toolbox-style zero-argument `ifconfig` output receive conservative structural validation. `ifconfig` availability and exact live output remain unknown; malformed, missing, privilege-seeking, or unparseable output stops with partial evidence. No `ip`, `netcfg`, BusyBox, extra argument, root, or retry is used. Empty IPv6 proc tables can be structurally valid and do not by themselves prove a phone-facing route. Offline decoding and privacy reduction remain subsequent analysis, not additional Honda commands.

Explicit outcomes are `SUCCESS`, `COMMAND_UNAVAILABLE`, `PERMISSION_DENIED`, `TIMEOUT`, `OUTPUT_LIMIT_EXCEEDED`, `UNEXPECTED_FORMAT`, `ADB_TRANSPORT_FAILURE`, `IDENTITY_MISMATCH`, `IDENTITY_INCOMPLETE`, `AMBIGUOUS_ADB_TARGET`, `UNEXPECTED_PRIVILEGE`, `USER_ABORT`, and `STOCK_SANITY_FAILURE`. Any non-success stops and preserves bounded private partial evidence. A host storage failure raises and halts without another target command. The future defensible target claim is at most `NO_INTENTIONAL_MUTATION_OCCURRED`, never `ZERO_PHYSICAL_STATE_CHANGE`.
